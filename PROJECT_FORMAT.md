# Описание проекта (`data` в `POST /api/v1/create_project/`)

Конфигуратор шлёт это описание вместе с именем и почтой пользователя, когда тот
нажимает «Отправить заявку». Сервер кладёт его как есть, возвращает ключ и
присылает ссылку в письме; страница, открытая по ссылке с `?project=<saveId>`,
читает описание обратно и восстанавливает состояние.

Расчёта здесь нет: смету бэкенд считает сам по этим данным. Участки обшивки
(`pieces`) совпадают с телом `calculate_facade` — их можно брать напрямую.

Собирает и применяет описание `project-io.js` (`buildProjectSnapshot`,
`applyProjectSnapshot`).

## Общие правила

- **Единицы — миллиметры**, целые числа. Углы — градусы, площади — квадратные
  метры (так их вводит пользователь).
- **Координаты плана** отсчитываются от левого верхнего угла участка: `x`
  вправо, `y` вниз. Сторона участка — `plot.sizeMm` (сейчас 32 000).
- **Неизвестное значение** — `null`; необязательный блок просто отсутствует.
- Разделы, которых нет в проекте, в `elements` не приходят.

## Корень

| Поле | Тип | Что это |
|---|---|---|
| `version` | число | Версия формата, сейчас `1`. Несовместимые изменения поднимут её |
| `app` | строка | Всегда `"shpuk-configurator"` |
| `savedAt` | строка | Время сборки описания, ISO 8601 в UTC |
| `units` | строка | Всегда `"mm"` |
| `plot.sizeMm` | число | Сторона квадратного участка |
| `house` | объект | Дом и его параметры |
| `elements` | объект | Благоустройство: ключ — раздел, значение — его состав |

## `house`

| Поле | Тип | Что это |
|---|---|---|
| `typeId` | строка | Идентификатор типа дома (`"type_09"`) или `"no_house"` для пустого участка |
| `areaM2` | число | Общая площадь дома |
| `foundationMm` | число | Высота фундамента |
| `floors` | список | По этажу: `index` (с нуля), `heightMm`, `areaM2` |
| `materials` | объект | `roof`, `base`, `wall`, `frame` — идентификаторы материалов дома |

## `elements`

Общий блок `product` есть почти у каждого раздела: `productId` — товар каталога,
`name` — его название на момент сохранения (справочно), `color` — цвет, если он
выбран вместо товара. Блока нет, когда товар не назначен.

| Раздел | Поля |
|---|---|
| `terrace` | `product`, `rects` (список `{x, y, w, h}`), `deckHeightMm` |
| `pool_terrace` | `product`, `rects`, `pool` (`{kind: "rect"｜"round", x, y, w, h}`) |
| `steps` | `product`, `items` (список `{x, y, w, h}`), `railing` (перила лестницы) |
| `paths` | `product`, `widthMm`, `points` |
| `fence` | `product`, `heightMm`, `points`, `gate` (`{x, y}`, если калитка есть) |
| `railing` | `product`, `postWidthMm`, `entries` (разрывы: `{t0, t1}` — доли периметра) |
| `beds` | `product`, `heightMm`, `mount` (тип крепежа), `items` |
| `furniture` | `items`: `{x, y, rotDeg, productId, name}` |
| `facade`, `facade2` | `product`, `segments`, `pieces` |

`points` у дорожек, забора и ограждения — список точек ломаной. Элемент
`{"break": true}` разделяет независимые линии: точки до него и после относятся к
разным ломаным.

`rects` и `items` — прямоугольники в плане: `x`, `y` — левый верхний угол.

### Отделка фасада

Отделок две и они равноправны: `facade` — «Отделка фасада 1», `facade2` —
«Отделка фасада 2». Кусок стены принадлежит одной из них.

- `segments` — идентификаторы выбранных кусков (`"f0:e3:s1b2"`, `"gable:west:s0"`).
  Нужны только конфигуратору: по ним восстанавливается выбор. Формат
  внутренний, полагаться на него не стоит.
- `pieces` — участки обшивки в том же виде, что принимает `calculate_facade`:
  `wallId` (ребро контура дома, нумерация с единицы в порядке обхода),
  `productId`, `vertices` (контур в системе стены: `x` вдоль стены от её начала,
  `y` вверх, миллиметры).

Высота в `pieces` считается от низа стен первого этажа, поэтому у двухэтажного
дома куски второго этажа идут выше на высоту этажа плюс перекрытие — промежуток
между этажами виден в координатах как есть.

Угловые столбы и пояс по линии карниза мансарды в `pieces` не входят: столбы
считаются уголками на стороне расчёта.

## Пример

```json
{
  "version": 1,
  "app": "shpuk-configurator",
  "savedAt": "2026-09-18T12:34:56.000Z",
  "units": "mm",
  "plot": { "sizeMm": 32000 },
  "house": {
    "typeId": "type_09",
    "areaM2": 120,
    "foundationMm": 800,
    "floors": [
      { "index": 0, "heightMm": 2900, "areaM2": 60 },
      { "index": 1, "heightMm": 2900, "areaM2": 60 }
    ],
    "materials": { "roof": "tile", "base": "beige", "wall": "white", "frame": "brown" }
  },
  "elements": {
    "terrace": {
      "product": { "productId": "196500", "name": "TalverWood Стандарт 150×25" },
      "deckHeightMm": 800,
      "rects": [{ "x": 14000, "y": 19650, "w": 4000, "h": 2000 }]
    },
    "fence": {
      "product": null,
      "heightMm": 1920,
      "points": [{ "x": 4800, "y": 28160 }, { "x": 27200, "y": 28160 }],
      "gate": { "x": 12260, "y": 28160 }
    },
    "facade": {
      "product": { "productId": "201100", "name": "Фасадная доска ДПК" },
      "segments": ["f0:e0:s0b1"],
      "pieces": [
        { "wallId": 1, "productId": "201100",
          "vertices": [{ "x": 250, "y": 900 }, { "x": 1980, "y": 900 },
                       { "x": 1980, "y": 2100 }, { "x": 250, "y": 2100 }] }
      ]
    }
  }
}
```

## Что проверять на сервере

- `version === 1`, `app === "shpuk-configurator"`, `units === "mm"`.
- `plot.sizeMm` — положительное число; координаты точек и прямоугольников лежат
  в пределах `0 … plot.sizeMm`.
- `house.typeId` — строка; `areaM2` и `foundationMm` положительные.
- В `elements` допустимы только известные разделы; внутри — типы полей из таблиц
  выше, все размеры неотрицательные целые.
- `pieces[].vertices` — минимум три точки, координаты неотрицательные.
